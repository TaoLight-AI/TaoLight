# 奢华健身管家：产品设计准则

## 北极星准则

用户填写、既往或实时的健康数据，必须转化为帮助用户完成目标的持续行动。若一条数据不能改变安全判断、今日行动、行动剂量或下一次调整，就不要求用户填写，也不占据主界面。

## 管家工作定义

系统持续理解用户 → 主动发现偏差 → 在后台完成分析 → 在合适时间只告诉用户一个决定 → 追踪执行结果 → 自动调整下一步。

“管家”不是拟人化说话方式，而是一套能够承担判断、追踪和调整责任的闭环。

## 不可妥协的设计原则

1. **原始数据不可改写**：用户输入、设备数据、推断结果和系统决定分层保存，任何减量决定不得反向修改健康事实。
2. **安全门控优先**：红旗信号先停止运动并明确线下就医边界；新发或加重的不适冻结进阶并暂停诱发动作。
3. **只在会改变决定时询问**：首次建基线、数据超过72小时、信号显著偏离、出现不适或准备进阶时才问；日常默认零输入。
4. **一次只给一个主要行动**：明确行动类型、剂量、时长、安全边界和保底版，不把选择压力转移给用户。
5. **最小有效剂量**：恢复日、精简版和保底版都是有效行动，不制造补偿训练、连续打卡或羞耻感。
6. **结果驱动下一步**：完成后只收集轻松、正好、吃力或不适；结果必须进入下一次剂量判断。
7. **一次只调一个变量**：吃力则下次减量约20%；恢复信号下降则减量20–30%或转恢复；连续两次轻松、恢复正常且无不适，才进阶5–10%。
8. **趋势优于单点**：体重、腰围、力量、HRV和睡眠评分按合理窗口与个人基线比较，不用单日波动下结论，不跨设备制造可比性。
9. **拒绝伪精确**：不用未经校准的“达成概率”；可以展示路径稳定度、证据完整度和决策置信度，并说明数据边界。
10. **人机边界透明**：本机分析、服务端分析、设备同步、真人专家和服务SLA分别标注真实能力，不把关键词规则包装成医学诊断。
11. **关卡替换而非功能堆叠**：每个目标周期和每日流程只展开当前最需要的一项功能；完成后原位替换为下一关，未到阶段的能力只显示锁定状态。
12. **结果之后检验体验**：系统给出并执行结果后，用一次点击验证“是否帮助行动、是否准确、是否仍太复杂”；体验反馈与健康反馈分开保存，用于下一轮产品优化。
13. **禁止无效按钮和死胡同**：每个主要按钮必须改变界面状态、生成用户需要的结果或明确解锁条件；“继续”不得只是返回已经完成的页面。
14. **模拟用户先于真实用户发现问题**：每次发布前自动遍历首次进入、数据过期、待行动、刚完成、体验已反馈和目标证据缺失等状态；任一路径没有下一步即阻止发布。

## 软件持续调整路径

| 阶段 | 系统责任 | 台前呈现 |
|---|---|---|
| 信号 | 汇总用户、历史与未来实时数据，标注来源、时间、新鲜度和可信度 | 只呈现影响当前决定的关键驱动 |
| 判断 | 风险门控，与个人基线比较，找目标当前最大约束 | 青春热度与一句因果解释 |
| 行动 | 生成唯一行动及结构化剂量 | 今天做什么、做多久、一个主按钮 |
| 验证 | 获取完成程度、主观难度和新不适 | 轻松 / 正好 / 吃力 / 不适 |
| 调整 | 根据结果只改变一个变量，保留决策版本与原因 | 因为什么，下一次改了什么 |

## 中年用户界面门槛

- 正文不小于16px，辅助文字不小于14px，核心数值不小于36px。
- 触控区不小于48×48px，主要按钮高度不小于52px。
- 首屏只回答两件事：我现在如何；今天做什么。
- 同一时刻只允许一个主要任务和一个主要按钮；已完成内容折叠，未来内容锁定，不把全部功能同时展开。
- 优先使用温度计、比例条、阶段环和状态路径，图形必须同时有文字标签，不能只靠颜色。
- Slogan“你比想象中的更‘强大’”保持单行、清秀、克制；奢华感来自留白、细金描边和精确对齐。

## 验收标准

- 稳定数据未超过72小时：不强迫每日填写，直接给出安全决定。
- 完成后选择“吃力”：原始数据不变，下一次训练量减少约20%，并显示原因。
- 连续两次“轻松”且无不适：只增加训练量5–10%，其他变量不变。
- 选择“不适”或输入红旗词：冻结进阶，进入安全流程，不出现庆祝文案。
- 刷新后结果和自动调整仍保留；同一健康事实可追溯到判断与行动。
- 375px宽时Slogan不换行；200%放大无横向滚动；5秒内能读懂青春热度和今日行动。
- 首次信号确认后界面原位替换为行动关；行动结果提交后原位替换为调整关，不跳转到旧版反馈弹窗。
- 体验检验只在结果产生后出现一次，提交后不重复弹出，并能区分“无帮助、不准确、太复杂”。
