# 专属私人AI教练：产品设计准则

## 北极星准则

用户填写、既往或实时的健康数据，必须转化为帮助用户完成目标的持续行动。若一条数据不能改变安全判断、今日行动、行动剂量或下一次调整，就不要求用户填写，也不占据主界面。

## 管家工作定义

系统持续理解用户 → 主动发现偏差 → 在后台完成分析 → 在合适时间只告诉用户一个决定 → 追踪执行结果 → 自动调整下一步。

“管家”不是拟人化说话方式，而是一套能够承担判断、追踪和调整责任的闭环。

## 不可妥协的设计原则

1. **原始数据不可改写**：用户输入、设备数据、推断结果和系统决定分层保存，任何减量决定不得反向修改健康事实。
2. **安全门控优先**：红旗信号先停止运动并明确线下就医边界；新发或加重的不适冻结进阶并暂停诱发动作。
3. **只在会改变决定时询问**：首次建基线、数据超过72小时、信号显著偏离、出现不适或准备进阶时才问；日常默认零输入。
4. **一次只给一个主要行动**：明确行动类型、剂量、时长、安全边界和保底版，不把选择压力转移给用户。
5. **最小有效剂量**：恢复日、精简版和保底版都是有效行动，不制造补偿训练、连续打卡或羞耻感。
6. **结果驱动下一步**：完成后只收集轻松、正好、吃力或不适；结果必须进入下一次剂量判断。
7. **一次只调一个变量**：吃力则下次减量约20%；恢复信号下降则减量20–30%或转恢复；连续两次轻松、恢复正常且无不适，才进阶5–10%。
8. **趋势优于单点**：体重、腰围、力量、HRV和睡眠评分按合理窗口与个人基线比较，不用单日波动下结论，不跨设备制造可比性。
9. **拒绝伪精确**：不用未经校准的“达成概率”；可以展示路径稳定度、证据完整度和决策置信度，并说明数据边界。
10. **人机边界透明**：本机分析、服务端分析、设备同步、真人专家和服务SLA分别标注真实能力，不把关键词规则包装成医学诊断。
11. **关卡替换而非功能堆叠**：每个目标周期和每日流程只展开当前最需要的一项功能；完成后原位替换为下一关，未到阶段的能力只显示锁定状态。
12. **结果之后检验体验**：系统给出并执行结果后，用一次点击验证“是否帮助行动、是否准确、是否仍太复杂”；体验反馈与健康反馈分开保存，用于下一轮产品优化。
13. **禁止无效按钮和死胡同**：每个主要按钮必须改变界面状态、生成用户需要的结果或明确解锁条件；“继续”不得只是返回已经完成的页面。
14. **模拟用户先于真实用户发现问题**：每次发布前自动遍历首次进入、数据过期、待行动、刚完成、体验已反馈和目标证据缺失等状态；任一路径没有下一步即阻止发布。
15. **完成必有当日成绩单**：取消打断用户的旧反馈弹窗，不等于取消反馈。每次行动结果提交后，当前关卡必须原位替换为当日身体成绩单，明确“完成了什么、完成得如何、对90天目标有什么意义、系统如何调整、下一次为何值得回来”。
16. **工具价值先于健康展示**：产品必须替用户完成记忆、计算或临场判断；若删除产品后用户完成训练的难度完全不变，该功能不具备进入主流程的资格。
17. **记住上次，带完这次，决定下次**：力量训练的最小服务单元从“今天练什么”下沉到“当前这一组”。系统沿用同动作历史，只要求用户修正发生变化的数据，并根据结果生成下一组与下一次处方。
18. **中断不补偿，只降复杂度**：时间不足时压缩为20分钟、两个动作、各一组的保底版；疲劳时采用最小有效剂量；不得在第二天叠加强度制造补偿性训练。
19. **不展示无证据的健康分数**：青春热度可作为品牌视觉语言，但在没有经验证模型前不得作为精确健康结论。台前优先显示训练许可、真实完成量、同类训练变化与下一步。
20. **每6次必须完成阶段复盘**：第6次行动完成后，系统必须汇总力量/恢复结构、有效余力、安全信号和同动作变化，明确哪些目标已有证据、哪些仍不能判断，并给出下一阶段唯一决定。报告不是资讯页，决定必须自动进入下一次处方。
21. **历史记录不得失忆**：版本升级后，已有账户记录必须进入阶段分析并标注来源；同日期同计划去重，本机新记录优先，不能让坚持过的用户重新从零开始。
22. **AI复核不替代规则安全门**：本机证据引擎先给出可解释的安全与剂量决定，服务端AI只能做第二重复核、发现遗漏和改善表达，不得推翻红旗停止、减量或专业转介。
23. **外部服务必须显示真实状态**：通知权限、后台能力、华为授权、AI服务端、专家席位与SLA分别检测。未审批、未部署或无人值守时明确显示“待接通”，禁止生成无人接收的工单或伪造已同步数据。
24. **随餐工具独立于训练关卡**：饮食发生在全天，不应塞进训练表单或阻塞今日训练。底部保留一个一触即达的“拍餐”入口，每次只处理当前餐次；训练页只引用已经确认的营养结果。
25. **照片是临时输入，确认结果才是健康数据**：食物照片只为本次识别临时传输，不进入训练档案；AI先识别食物与份量，再由营养数据库计算蛋白质和热量。用户确认或校正后才计入全天，并转化为下一餐的一个行动决定。
26. **校正必须重新计算而非只改标签**：识别错误时，用户可直接用自然语言修改食物和份量；系统必须重新解析并调用营养数据计算热量与蛋白质。新结果恢复为“待确认”，再次确认后才替换全天累计，禁止出现食物名称已改而营养数字沿用旧值。

## 软件持续调整路径

| 阶段 | 系统责任 | 台前呈现 |
|---|---|---|
| 信号 | 汇总用户、历史与未来实时数据，标注来源、时间、新鲜度和可信度 | 只呈现影响当前决定的关键驱动 |
| 判断 | 风险门控，与个人基线比较，找目标当前最大约束 | 青春热度与一句因果解释 |
| 行动 | 生成唯一行动及结构化剂量 | 今天做什么、做多久、一个主按钮 |
| 验证 | 获取完成程度、主观难度和新不适 | 轻松 / 正好 / 吃力 / 不适 |
| 调整 | 根据结果只改变一个变量，保留决策版本与原因 | 因为什么，下一次改了什么 |
| 反馈 | 将行动快照、主观难度与目标关联，生成当日总结和次日预案 | 今日成绩单：行动、质量、意义、调整、期待 |

## 中年用户界面门槛

- 正文不小于16px，辅助文字不小于14px，核心数值不小于36px。
- 触控区不小于48×48px，主要按钮高度不小于52px。
- 首屏只回答两件事：我现在如何；今天做什么。
- 同一时刻只允许一个主要任务和一个主要按钮；已完成内容折叠，未来内容锁定，不把全部功能同时展开。
- 优先使用温度计、比例条、阶段环和状态路径，图形必须同时有文字标签，不能只靠颜色。
- Slogan“你比想象中的更‘强大’”保持单行、清秀、克制；奢华感来自留白、细金描边和精确对齐。

## 验收标准

- 稳定数据未超过72小时：不强迫每日填写，直接给出安全决定。
- 完成后选择“吃力”：原始数据不变，下一次训练量减少约20%，并显示原因。
- 连续两次“轻松”且无不适：只增加训练量5–10%，其他变量不变。
- 选择“不适”或输入红旗词：冻结进阶，进入安全流程，不出现庆祝文案。
- 刷新后结果和自动调整仍保留；同一健康事实可追溯到判断与行动。
- 375px宽时Slogan不换行；200%放大无横向滚动；5秒内能读懂青春热度和今日行动。
- 首次信号确认后界面原位替换为行动关；行动结果提交后原位替换为调整关，不跳转到旧版反馈弹窗。
- 体验检验只在结果产生后出现一次，提交后不重复弹出，并能区分“无帮助、不准确、太复杂”。
- 今日成绩单必须保留行动当时的名称、剂量、内容、身体状态与结果，刷新后不因次日计划变化而改写历史。
- 疼痛或异常不适不得出现庆祝式结论；必须显示冻结进阶、安全处置和专业服务边界。
- 老用户打开后5秒内必须看到今天是否训练、预计用时和第一个动作；训练中任一时刻只显示当前组。
- 第二次同类训练默认沿用历史重量与次数；除非数据发生变化，用户不重复填写。
- “器械被占”“只有20分钟”“明显疲劳”“疼痛或异常”必须在当前流程内产生替代、减量或停止决定，不能把问题重新交还给用户。
- “拍餐”从任意主界面最多一次点击到达；支持照片、文字、照片＋文字。识别结果必须展示热量、蛋白质、误差区间/置信度和校正入口，未经确认不得计入全天。
- 确认一餐后必须立即更新全天蛋白质与热量，并只给一个下一餐决定；不因单餐或单日估算直接改变长期训练计划。
- 食物照片不得写入本机档案或上传到训练记录存储；界面必须准确说明照片会临时发送至识别服务，禁止使用“完全不上传”等误导文案。
- 修改已识别的食物或份量后，“按修改重新计算”必须同时更新食物明细、热量、蛋白质、区间与置信度；重算结果未经再次确认不得计入全天，已确认餐次不得重复累计。
- 第6次有效行动完成后，今日成绩单必须解锁综合反馈；综合反馈至少包含3条可追溯证据、1个数据缺口和1个已写入下一阶段处方的决定。
- 旧版账户已有6条记录时，不要求重新打卡；迁移后应直接生成第1阶段报告，并避免与本机同日同计划记录重复计算。
- 服务端AI不可用时，本机阶段报告仍完整可用并标注来源；AI恢复后可复核，但不能改变安全门控。
- 未完成华为开发者审批时不得出现“已同步”；未配置专家名单与排班时不得允许提交工单；不支持后台周期任务的浏览器不得声称可保证离线准时提醒。
